Urban Climate Tools — Deployment Checklist

Static Astro site → Bluehost. Print this page or keep it open while you deploy.

Important — "Bluehost / WordPress" decision. This is a static site (plain HTML/CSS/JS produced by Astro). It does not import into WordPress as a theme or posts. You have two realistic paths on Bluehost:
  • Path A — Static hosting recommended: upload the built dist/ folder straight to public_html. Fastest, cheapest, nothing to maintain. WordPress not involved.
  • Path B — Keep WordPress: only if you need WP's CMS/login. You'd serve this site from a subfolder (e.g. yourdomain.com/tools/) alongside WP, or replace WP entirely. Mixing them at the root causes conflicts.

0 · Pre-flight (do these first)

These are open issues found in QA that affect the live site. Fix before building the final upload.

  • Set the real domain in astro.config.mjs → site: (currently https://urbanclimatetools.org). This drives canonical URLs, OG tags, and the sitemap. If hosting in a subfolder, also add base: '/subfolder'.
  • Decide tools content strategy. The 19 tools are illustrative — homepage/github links and citedBy counts are fabricated. "Visit homepage" buttons currently point to dead URLs. Either swap in real tools (i-Tree, NOAA SLR Viewer, EPA Stormwater Calc, etc.) or add a visible "illustrative/demo" disclaimer.
  • Fix category filter links. Footer, homepage category grid, data explorer, and case-study theme chips all link to /tools?cat=heat, but the Tools page ignores the ?cat= param — every one lands unfiltered. (Fix: read URLSearchParams on load and pre-select the category.)
  • Update the footer logo — it still uses the old hand-coded SVG circle instead of the real logo-light/dark.png used in the header.
  • Add a 404 page (src/pages/404.astro). Astro outputs 404.html; Bluehost/Apache serves it automatically.
  • Add public/robots.txt pointing to the sitemap (Sitemap: https://yourdomain.com/sitemap-index.xml).
  • Case-study photos: only 5 of 13 have images (bogota, copenhagen, rotterdam, singapore, phoenix). paris.jpg and minneapolis.jpg exist but have no matching case study. Source photos for the other 8 (amsterdam, cape-town, dhaka, lagos, medellin, melbourne, miami, tokyo) or the cards look uneven.
  • Compress the hero video — hero.mp4 is 25 MB (the whole site is 28 MB). Target ≤5 MB, add a poster image, and consider not autoplaying on mobile.

1 · Build the site

  • Confirm Node ≥ 22.12 (node -v).
  • From the project folder, run a clean production build:
cd "/Users/mkws/urban-climate-tools"
npm install
npm run build
The build script also runs Pagefind, which generates the /pagefind search index. Search only works in the built output — not in npm run dev. Test locally with npm run preview before uploading.
  • Verify dist/ contains: index.html, tools/, case-studies/, data/, about/, portfolio/, search/, pagefind/, sitemap-index.xml, 404.html, and your assets.
  • Open dist/ via npm run preview and click through every nav item + the search page once.

2 · Prepare Bluehost

  • Log in to Bluehost → Hosting → cPanel.
  • Point your domain/subdomain at the right docroot (Domains → ensure it maps to public_html or your chosen subfolder).
  • Back up anything already in public_html (especially if WordPress lives there — Path B).

Path A — Replace root with the static site recommended

  • Open cPanel → File Manager → public_html.
  • If the folder has an old/default site, move it to a backup folder or delete it.
  • Upload the contents of dist/ (not the dist folder itself) into public_html. Zip dist/ first, upload the zip, then "Extract" in File Manager — far faster than uploading thousands of small files.
  • Confirm public_html/index.html exists at the top level.

Path B — Serve from a subfolder alongside WordPress only if keeping WP

  • Set base: '/tools' (your subfolder name) in astro.config.mjs and rebuild — otherwise CSS/JS/asset paths 404.
  • Create public_html/tools/ and upload dist/ contents there.
  • Make sure WordPress's permalinks/rewrite rules don't capture /tools (add an exclusion in the root .htaccess if needed).

3 · Server config (.htaccess)

Create/append .htaccess in the docroot. This handles HTTPS, a clean 404, caching, and gzip — Apache/Bluehost reads it automatically.

# Force HTTPS
RewriteEngine On
RewriteCond %{HTTPS} off
RewriteRule ^ https://%{HTTP_HOST}%{REQUEST_URI} [L,R=301]

# Custom 404
ErrorDocument 404 /404.html

# Cache static assets (Astro hashes filenames, safe to cache long)

  ExpiresActive On
  ExpiresByType text/css "access plus 1 year"
  ExpiresByType application/javascript "access plus 1 year"
  ExpiresByType image/jpeg "access plus 6 months"
  ExpiresByType image/png "access plus 6 months"
  ExpiresByType video/mp4 "access plus 6 months"
  ExpiresByType text/html "access plus 0 seconds"


# Gzip

  AddOutputFilterByType DEFLATE text/html text/css application/javascript application/json image/svg+xml
  • Upload .htaccess to the docroot (enable "Show Hidden Files" in File Manager to see it).

4 · SSL / HTTPS

  • cPanel → SSL/TLS Status → ensure the domain has an active (AutoSSL/Let's Encrypt) certificate. Bluehost usually provisions this automatically; "Run AutoSSL" if missing.
  • Load https://yourdomain.com and confirm the padlock shows with no mixed-content warnings.

5 · Post-deploy verification

  • Home page loads; hero video plays; frosted header sits over it.
  • Light/dark toggle switches the whole page and persists on reload.
  • Every nav link works: Tools, Case Studies, Data, About, Search.
  • Open one tool detail and one case-study detail page (deep links work, not just nav).
  • Search page returns results (confirms /pagefind uploaded correctly).
  • Leaflet maps render (homepage + case-study mini-map).
  • Logo, favicon, and city photos all load (no broken-image icons).
  • Visit a fake URL (/nope) → custom 404 shows.
  • Check on a phone: header, video, nav menu, tap targets.
  • https://yourdomain.com/sitemap-index.xml resolves; submit it in Google Search Console.
  • Run PageSpeed Insights — watch the video's effect on mobile LCP.
  • Test an OG link preview (paste the URL into Slack/iMessage) → image + title appear.

6 · Updating the site later

There's no live CMS — content lives in Markdown files. To publish changes:

1. Edit/add files in src/content/tools or src/content/case-studies
2. npm run build
3. Re-upload the changed files in dist/ (or re-zip & extract)
The weekly GitHub Action drafts new content as a pull request. Your flow stays: review & merge the PR → pull locally → npm run build → re-upload. Bluehost has no build step, so the build always happens on your machine (or in CI).
